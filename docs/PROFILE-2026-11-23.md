## Diagnosis

| Class | Cause and supporting measurement |
| --- | --- |
| Consumer-local path | The harness runner duplicates the shared runner's job and caps its own pool (`safe-agent-harness/tests/run_tests.py:26,84`, quoted). The quoted 900 s and 18 TMPDIR entries show that the rerun hit its deadline with temporary state still present. The gate enumerates then removes that directory (`quality_gate/python_tests.py:520–542`, `quality_gate/checks.py:696–709,749–775`). A timeout cannot identify work outstanding, the cost of cleanup, how long a completed run would take, or how much the shared runner would save. |
| Policy setting under a CPU quota | The profiled revision used `os.cpu_count()` alone for the default (`quality_gate/test_shards.py:358–366`). With a three-CPU quota on the local failing workload, increasing workers from six to twelve cost 15.288 s on average. Three workers were slower than six, so the quota alone does not select the fastest count. The quoted pair from outside any lane (load about 6) favoured more workers, with 73.6 s at four and 34.7 s at twelve. The conditions differ across these runs and leave a general default unverified. |
| Gate defect | Two runner test fixtures inherit their caller's process group and use group-based teardown. The focused launch comparison isolated 10.006 s of avoidable waiting across two passing fixture tests (`tests/test_runner.py:46–56,213–225`). |
| Gate defect | The scheduler balances unit counts by intact fixture block, ignoring duration (`quality_gate/test_shards.py:110–132,294–308`). The worker counts were close while finish times differed sharply. A fixed-duration replay grouped the measured test times by intact fixture block, sorted blocks by descending time and put each on the least-loaded of twelve workers. It lowered the largest sum from 46.159 s to 27.265 s (18.893 s using unrounded values). It assumes measured durations remain fixed as contention changes and excludes fixture setup, so it is a schedule model. |
| Gate defect | The parent and each worker repeat discovery, and each worker reads the plan and journals results (`quality_gate/test_shards.py:42–57,230–240,266–277,294–308,382–399`). Initial discovery measured 0.261 s in the parent and 0.609–1.217 s per worker. A worker's discovery wall overlaps with the other workers. The rediscovery and journal validate fixture and worker integrity. The measured amount bounds the observed phase, with no evidence that removing it would preserve suite behavior. |
| Gate defect | Checks execute one after another, with each result inserted into `prior` before the next starts (`quality_gate/checks.py:813–863`). The static run spent 1.924 s summed across timed checks versus 1.006 s in its longest check, a 0.919 s zero-contention overlap ceiling across those calls. In the quoted policy-check rows, serial time other than the longest was 32.9–<33.5 s for the timed-out harness, 10.2–<15.2 s for the editor and at least 0.8 s for self-gate. These are derived sums of the quoted durations. Evidence dependencies, shared CPU, and command isolation reduce achievable overlap. The subprocess runner also tracks process-wide adopted children, and check/run deadlines are process-wide (`quality_gate/runner.py:77–99,322–378,646–711`, `quality_gate/checks.py:825–862`). |
| Gate defect | Each Elisp check repeats an Emacs version subprocess (`quality_gate/elisp_tests.py:85–104,377–390`, `quality_gate/elisp_crap.py:294–299`, `quality_gate/elisp_lint.py:209–215`).
